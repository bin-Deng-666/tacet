每天点开 B 站，第一眼不是首页，是一张开屏海报。

右上角有个「跳过」，很小。有时晚一秒才出现，有时被进度圈挡着。你得盯着它，手指停在那个位置，等它能按了才按下去。

三秒不长。但一天打开五六次，一年就是两千多次。

我写了个小工具，名字叫「清净」（项目名 Tacet）。它只干一件事：开屏一出来，替我把跳过点掉。现在点开图标，闪一下，直接进首页。

它的目标很窄：**只去掉"打扰"这一类广告，不碰应用里的正常内容。**

## 它做什么

三件事：

**一、按应用拦截广告域名**

用 Android 自带的 `VpnService` 建一个只接管 DNS 的本地接口。它不做全流量转发，只把两个虚拟 DNS 地址路由进来，普通视频、网页请求照旧走原来的网络。

域名匹配按 DNS 标签边界做，`ads.example.com` 会命中，`notads.example.com` 不会。白名单优先于黑名单。

**二、自动跳过开屏和切回前台**

用无障碍服务监听窗口变化，匹配到"跳过"控件就点掉。每次切换回应用都会重新匹配，所以从后台回来弹出的开屏也能处理。

**三、两项能力按应用分别开关**

每个应用都有"自动跳过"和"拦截广告请求"两个独立开关。B 站默认只开跳过，不开域名过滤。

## 为什么 B 站不开域名过滤

这是我做这个工具时最重要的一个决定。

最早版本是"全都拦"，结果会影响应用内的内容和推荐。查了 B 站的开屏数据来源才明白：开屏广告走的是 `/x/v2/splash/*` 这几个接口，**和正常业务共用主域**。

也就是说，没法只拦开屏请求而不伤到正常功能。

所以最终方案是：B 站只保留"事后点掉跳过"，应用内部一律不碰。

## 先说做不到的

这部分我写在 README 第一屏，这里也完整列出：

1. **开屏会短暂闪现。** 自动跳过是界面出现之后才能点的动作，原理上必然先显示再消失。想完全不显示，只能修改客户端本身。
2. **同一时间只能跑一个 VPN。** Android 的限制，本应用和代理类工具互斥。检测到别的 VPN 时不会抢占，只会提示。
3. **共用接口的广告拦不掉。** 和正常内容一起返回的广告字段，DNS 过滤没法单独删。
4. **规则跟着应用版本走。** 应用更新可能改控件标识或域名，需要重新适配。

## 技术细节

- 纯 Java，无第三方依赖，851 行源码。
- 构建不依赖 Gradle：`aapt2` + `javac` + `d8` + `apksigner` 直接出包，不需要联网下载依赖。
- APK 90KB。
- 只用 Python 标准库的构建脚本。

DNS 这一层自己实现了报文解析和应答构造，包括 IPv4/IPv6、UDP/TCP 双栈。测试覆盖了畸形报文、标签指针、分片、校验和这些容易出错的地方。

## 测试情况

- 37 项核心协议检查（域名边界、白名单优先级、畸形 DNS 报文、IPv4/IPv6 包长与校验和）
- 44 项手机端真实接口检查（双栈 UDP/TCP、白名单热更新、三轮开关释放与恢复、应用选择变更）
- B 站实测：冷启动、后台 70 秒、后台 130 秒后返回，三次都成功跳过开屏
- 养基宝实测：冷启动与后台返回时拦截到穿山甲、优量汇的广告请求

需要说明的是，协议测试通过不等于真实应用里的广告都被去除，这两件事我分开验证。

## 代码

开源，MIT 许可：

```
github.com/bin-Deng-666/tacet
```

需要 Python 3、JDK 17、Android SDK Platform 35 与 Build Tools 35.0.0。

```sh
python3 build.py --sdk /path/to/android-sdk --java /path/to/jdk --test
```

不需要 Gradle，也不需要联网下载依赖。

## 最后

这个工具解决的是很窄的一个问题：开屏和切回的打扰。它不会让应用里的广告消失，也不打算那么做。

如果你也受不了那三秒，可以拿去用。
